## Детальное описание шагов сценария

### 1. Авторизация в системе
- **Действие**: Вход в систему с логином и паролем
- **Проверка**: 
  - Корректная валидация учетных данных
  - Получение JWT токена
  - Перенаправление на главную страницу
- **Тестовые данные**: admin / admin123

### 2. Регистрация клиента
- **Действие**: Создание нового клиента (физ. или юр. лицо)
- **Проверка**:
  - Валидация ИНН (10 или 12 цифр)
  - Валидация банковских реквизитов
  - Сохранение данных в БД
- **Тестовые данные**: 
  - ФИО: Тестов Тест Тестович
  - ИНН: 500100732271
  - Тип: INDIVIDUAL

### 3. Проведение скоринга
- **Действие**: Автоматическая оценка кредитоспособности
- **Проверка**:
  - Расчет балла (0-100)
  - Базовый балл: 50
  - +10 за ИНН, +10 за юрлицо, +5 за банк. счет
  - Автоматическое решение по баллу
- **Ожидаемый результат**: 
  - ≥70 → AUTO_APPROVED
  - 50-69 → MANUAL_REVIEW
  - <50 → REJECTED

### 4. Добавление оборудования
- **Действие**: Регистрация единицы оборудования
- **Проверка**:
  - Заполнение обязательных полей
  - Привязка к категории
  - Установка статуса AVAILABLE
- **Тестовые данные**:
  - Название: Холодильная витрина Test
  - Цена: 100000.00
  - Категория: Холодильное оборудование

### 5. Создание договора
- **Действие**: Оформление лизингового договора
- **Проверка**:
  - Автогенерация номера (ЛД-2026-XXX)
  - Выбор клиента и оборудования
  - Расчет суммы договора
  - Установка дат начала/окончания
- **Тестовые данные**:
  - Клиент: Тестов Т.Т.
  - Оборудование: Холодильная витрина Test
  - Срок: 24 месяца
  - Ставка: 8.5%

### 6. Генерация графика платежей
- **Действие**: Автоматический расчет аннуитетных платежей
- **Проверка**:
  - Количество периодов = срок договора
  - Расчет основного долга и процентов
  - Корректность дат платежей
- **Формула**: A = P × (r × (1+r)^n) / ((1+r)^n - 1)

### 7. Активация договора
- **Действие**: Смена статуса DRAFT → ACTIVE
- **Проверка**:
  - Изменение статуса договора
  - Изменение статуса оборудования (AVAILABLE → LEASED)
  - Запись в audit_log

### 8. Регистрация платежей
- **Действие**: Фиксация поступления денежных средств
- **Проверка**:
  - Привязка к графику платежей
  - Изменение статуса (PENDING → PAID)
  - Расчет остатка задолженности
- **Тестовые данные**:
  - Сумма: согласно графику
  - Способ: BANK_TRANSFER
  - Дата: текущая

### 9. Мониторинг просрочек
- **Действие**: Просмотр просроченных платежей
- **Проверка**:
  - Автоматическое определение просрочек
  - Отображение в дашборде
  - Статус OVERDUE для просроченных
- **Критерий**: payment_date < текущая дата И status = PENDING

### 10. Экспорт отчётов
- **Действие**: Выгрузка данных в Excel
- **Проверка**:
  - Генерация XLSX файла
  - Корректность данных
  - Форматирование таблиц
- **Форматы**: 
  - Один договор
  - Все договоры

```

   [Балл < 50]

   Отклонение → Уведомление менеджера → ЗАВЕРШЕНИЕ
```

## Проверяемые аспекты

### Функциональное тестирование
- ✓ Корректность бизнес-логики
- ✓ Валидация входных данных
- ✓ Расчетные операции
- ✓ Изменение статусов
- ✓ Связи между сущностями

### Тестирование UI
- ✓ Отображение данных
- ✓ Работа форм
- ✓ Навигация между страницами
- ✓ Обработка ошибок
- ✓ Адаптивность интерфейса

### Тестирование безопасности
- ✓ Аутентификация и авторизация
- ✓ Защита от SQL-инъекций
- ✓ Валидация на стороне сервера
- ✓ Безопасное хранение паролей (BCrypt)
- ✓ JWT токены с истечением срока

### Тестирование производительности
- ✓ Время загрузки страниц (<2 сек)
- ✓ Время выполнения запросов к БД (<500 мс)
- ✓ Обработка больших объемов данных
- ✓ Параллельные запросы пользователей
